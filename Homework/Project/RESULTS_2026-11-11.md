## Direct English/Lean argument comparison

Original unquantized BF16 Qwen3-14B was compared with a fresh LoRA trained on the
new related-proof dataset. It used366 balanced training examples, one epoch,
rank16, learning rate1e-4,46optimizer steps and20,971,520 trainable parameters.
Training took2138.72seconds (35.65minutes), peaked at39.81GiB GPU memory, and
skipped no training rows. The adapter is saved locally under the ignored run.

The source pairs contain both statements and proof bodies. Source matches are
assumed under the user's policy; negatives swap a related English statement and
proof together against the original Lean side. Relatedness must be at least0.20.
The new family split is70/15/15 before filtering; final labeled counts are
366training,60validation,54test. Independent checks found no family/shared-proof
overlap and reproduced frozen hashes and prediction IDs.

On the16-pair diagnostic, which crosses different valid argument routes for four
theorems, both accept all8matching routes. Original Qwen catches7/8mismatches;
the new adapter catches3/8 and falsely accepts5/8. This remains a weakness in
detecting changed arguments when the theorem is unchanged. However, both models
still rank every true match above every mismatch (AUROC1.0). The tuned minimum
positive YES-minus-NO logit margin is10.25; maximum negative margin10.0. The fixed
decision boundary is0, so the ranking and binary decisions tell different stories.
Do not infer that reasoning was destroyed or select a threshold on this diagnostic.

These new results are not a controlled comparison with the older random-swap
percentages: the split, source coverage and swap transformation changed. The
older run swapped only English proofs; this run keeps the English statement and
proof coherent. Related bundles can differ in conclusions or assumptions, so
high accuracy here does not establish subtle same-theorem argument fidelity.
The test is held out from this adapter, but the public corpus was used in earlier
experiments. Labels remain assumed/synthetic rather than independently audited.

## Original Qwen with independent translation intermediaries

All four architectures use the original pretrained model, without the new LoRA.
Each translation sees only its own source view. Scores below concern textual
semantic comparisons and are conditional on a completed judgment. Missing,
truncated and over-context translations are abstentions, not semantic negatives.

| Architecture | New test scored | Correct / scored | Accuracy on scored pairs | Old diagnostic correct / scored |
| --- | ---: | ---: | ---: | ---: |
| English to Lean, compare Lean arguments | 13/54 | 9/13 | 69.23% | 12/12;4unscored |
| Lean to English, compare English arguments | 48/54 | 33/48 | 68.75% | 16/16 |
| Both to Verbose Lean, compare generated arguments | 35/54 | 20/35 | 57.14% | 16/16 |
| Both to Natural Lean, compare generated arguments | 42/54 | 26/42 | 61.90% | 16/16 |

The methods score different subsets, so these percentages alone do not rank
architectures fairly. None falsely accepts a scored synthetic mismatch on the
new test; their errors are rejections of assumed matches, with many additional
unscored pairs. Class-specific coverage and full metrics are in the aggregate
JSON. The16-pair result is promising for comparing argument routes through
English, but comes from only four previously inspected theorem families.

English-to-Lean test exclusions include36truncated outputs,4admitted outputs
and1comparison exceeding context. Lean-to-English has6truncated outputs.
Thus generation-token limits contribute materially to the low coverage; these
results do not establish that unlimited or differently trained generation would
fail similarly. Inspected formal failures include obsolete Lean3syntax,
nonexistent imported modules and invalid dialect grammar, rather than missing
installed environments. One Verbose-target diagnostic translation invents an
extra assumption despite a correct final pair label, illustrating why even
correct downstream judgments do not establish faithful intermediate generation.

All three code-producing architectures have zero comparison pairs for which
every generated code branch passed the recorded compiler checks. Of35unique
English-to-Lean outputs, none compiled; of70Natural Lean outputs, none compiled.
Two of70Verbose-target outputs compiled, but inspection found they are ordinary
Mathlib Lean from the formal branch, not actual Verbose-dialect translations.
They do not produce a pair with both branches compiled. Thus the text-based
scores do not demonstrate a functioning verified Lean/dialect intermediary.

Both dialect environments and upstream examples were built before checking.
The separate ledger distinguishes parser/type failures, incomplete generation,
unsupported imports, executable-extension screening and timeout. The conservative
screen can reject words inside string literals; screening rejections are not
compiler failures. Compilation itself would still not certify source fidelity.
